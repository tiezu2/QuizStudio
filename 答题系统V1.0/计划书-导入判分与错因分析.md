# QuizStudio 计划书：导入智能判缺 + 自选模型 + 错因分析

> 本文只是计划，不含任何代码改动。落手实现前请确认里程碑与验收标准。

## 一、要解决的三个问题

1. **导入没答案的卷子会引入一堆错答案**（AI 补答案在「选出错误的」类题上系统性反向，且解析与答案键互相矛盾）。
2. **AI 模型不可选**——现在写死 `glm-4-flash`，用户没法换更准的模型或本地模型。
3. **提交后只知道对错，不知道为什么错**——错题没有逐题分析。

## 二、方案总览

```
导入卷子
  │
  ├─ 步骤 1【双轨判定】这卷子有没有答案？
  │    ├─ 有 → 直接用导入的答案，AI 只写解析、不改答案
  │    └─ 无 → AI 生成答案（按下面"极性感知"流程），标记 _aiAnswer
  │
  ├─ 步骤 2【极性感知补答案】
  │    ├─ 先让模型只判每个选项的"说法真假"（A:true/B:false…），不给答案键
  │    ├─ 按题干极性推答案：含「错误的/不正确的/不属于」→ 取 false 项，否则取 true 项
  │    └─ 写入后立刻校验"答案键 = 解析结论 = 真值"，不一致标 _needsReview
  │
  └─ 步骤 3【写解析】按真值逐选项写「说法正确/错误 + 理由」，结论行由服务端生成（不由模型自由发挥）

答题提交
  │
  └─ 步骤 4【错题逐题分析】只对判错的题调模型，输出：错因类型 + 具体原因 + 改正要点

设置页
  │
  └─ 步骤 5【模型选择】AI 设置里可选 provider/model，导入/写解析/错因分析分别可配
```

## 三、模块设计

### 3.1 导入前的答案双轨判定

| 情况 | 判定规则 | 处理 |
|---|---|---|
| 全卷有答案（≥95% 题有 `answer` 或 `ref`） | 视为「有答案卷」 | 直接用，AI 不碰答案 |
| 全卷有答案但部分缺失 | 视为「部分有答案」 | 有的保留，缺的走 AI（并标记来源） |
| 全卷基本无答案 | 视为「无答案卷」 | 全部走 AI，题目打 `_aiAnswer=1` |

字段：
```js
q.answerSrc = 'import' | 'ai'   // 答案来源，界面上区分显示
q._needsReview = true           // 自检不通过时置位，界面显示「⚠ 待复核」
```

### 3.2 极性感知补答案（核心，解决"选正确的被反转"）

1. **第一轮**：只发题干 + 选项，不告诉模型答案，要求输出每个选项的真假
   ```
   输入：题干 + A/B/C/D
   输出：{"A": true, "B": false, ...}   // 该选项说法本身对/错
   ```
2. **第二步（纯规则，不用 AI）**：判定题干极性
   - 命中 `错误的是|不正确的|不属于|不是|不包括|有误` → 答案 = 真值为 `false` 的选项
   - 否则 → 答案 = 真值为 `true` 的选项
   - 单选题多解时取「唯一 true/false」那项；仍有歧义 → 标 `_needsReview`
3. **第三步**：写回 `answer`，并把 `A:true/false` 存进 `q._truth`，供解析和校验复用

### 3.3 解析生成（结论由服务端定，不由模型写）

- 选项行：「A．说法正确 —— 理由」，词由 `q._truth` 决定，**模型只写理由**
- 结论行：「结论：本题选 X —— 一句话」，**X 由服务端按答案键填**
- 这样从结构上杜绝"解析说 C、答案存 A"

### 3.4 自选大模型

配置界面（新增「AI 设置」弹窗）：
| 用途 | 可选项 | 默认 |
|---|---|---|
| 补答案 | glm-4-flash / glm-4.5-flash / qwen2.5-3b（本地） | glm-4-flash |
| 写解析 | 同上 | 客观题 glm-4-flash，大题 glm-4.5-flash |
| 错因分析 | 同上 | glm-4.5-flash（分析要细） |

配置写到 `quiz_studio_llm.json`：
```json
{
  "models": {
    "answer": "glm-4-flash",
    "explain": { "objective": "glm-4-flash", "heavy": "glm-4.5-flash" },
    "diagnose": "glm-4.5-flash"
  }
}
```
界面提供「测试连接」按钮，显示耗时与返回样例。

### 3.5 提交后的错题分析

触发：点「提交评分」→ 客观题本地判分 → **只把判错的题**送模型（省额度）。

输出结构（每题）：
```json
{
  "qid": "q12",
  "errorType": "概念混淆 | 审题（问错误的） | 语法细节 | 记忆不准 | 计算失误",
  "reason": "你把「抽象类必须有抽象方法」当成正确，实际上抽象类可以没有抽象方法",
  "fix": "记住：抽象类只是不能被实例化，是否含抽象方法是可选的"
}
```

界面：错题卡片下方显示
```
❌ 概念混淆
   你把「抽象类必须有抽象方法」当成正确……
   👉 记住：抽象类只是不能被实例化……
```

数据落 `DB.report.items[].diag`，可导出到诊断报告页。

## 五、验收标准

1. 导入一份**无答案**卷子：所有题答案来源标 `ai`，且「选出错误的」类题不再反向
2. 导入一份**有答案**卷子：AI 不改任何 `answer`，只补解析
3. 全库跑 `audit_answers.py`：`_needsReview` 数量 ≤ 5%（约 366 道独立题里 ≤18 道）
4. 提交一份 20 题卷子：错题每题都有错因类型 + 原因 + 改正要点，生成耗时 ≤ 30 秒
5. 设置页能把「错因分析」切成 `qwen2.5-3b`（本地）并跑通

## 六、风险与对策

| 风险 | 对策 |
|---|---|
| 真值判断本身也可能错 | 三份证据（真值/解析/答案键）不一致时不静默改，标 `_needsReview` 交人工 |
| 逐题判真假费额度 | 批量 20 题/次；有答案的卷子完全跳过 |
| 大模型选择过多导致配置混乱 | 只暴露 3 个用途 × 3 个模型，不开放任意 URL（保持可控） |
| 错因分析对小模型质量差 | 本地模型只用于判分/解析，错因分析默认走在线模型 |

## 七、里程碑

| 阶段 | 内容 | 预计 |
|---|---|---|
| M1 | 极性感知补答案 + 服务端定结论 + `audit_answers.py` | 3~4 小时 |
| M2 | 自选模型（设置弹窗 + 配置读写 + 测试连接） | 2 小时 |
| M3 | 提交后错题逐题分析（接口 + 界面 + 报告导出） | 2~3 小时 |
| M4 | 全库跑 audit 修正存量题（约 30 道待复核逐条确认） | 1 小时 + 人工确认 |

## 八、需要你确认的三点

1. **有答案的卷子**：AI 完全不碰答案，只写解析——确认吗？
2. **错因分析**：只分析判错的题（省额度），还是要分析全部？
3. **自选模型**：只允许在「智谱 / 本地 qwen」里选，还是要支持填任意 OpenAI 兼容地址（更灵活但更难排查）？

## 九、面向其他用户（非开发者）的补充设计

上面 M1~M4 是按「功能」拆的；如果这套东西要给**别的同学/老师**用，还得补一层「他们不会改 json、不会装 Python、出错了也不会看日志」的设计。

### 9.1 零配置可用（默认不花钱、不报错）

| 场景 | 默认行为 |
|---|---|
| 没配 API Key | 客观题本地判分、解析显示已有内容；**AI 相关按钮置灰并提示「未配置 AI，可继续做题」，不弹错误** |
| 导入无答案卷子且无 Key | 提示「这份卷子没有答案，需要 AI 补答案；请先在设置里填 Key，或手动补答案后导入」，**不静默导入一堆无答案题** |
| 桌面版 exe | 双击即用，不要求装 Python；数据存 `%LOCALAPPDATA%\QuizStudio\`，升级不丢 |

### 9.2 设置全部进界面（不允许手改文件）

新增「设置」页，三块：
1. **AI 设置**：模型选择 + Key 输入 + 「测试连接」（显示耗时/样例）、是否启用
2. **导入设置**：遇到无答案卷子的策略（AI 补 / 只导入有答案的 / 允许无答案但不判分）
3. **数据设置**：导出题库 / 导入题库 / 打开数据目录 / 清空作答记录（关闭即清已有，这里做全局）

配置文件仍落 `quiz_studio_llm.json`，但**用户不需要知道它的存在**。

### 9.3 出错时给人话，不给堆栈

| 出错点 | 提示文案（界面 toast） |
|---|---|
| Key 无效 | 「AI Key 无效或已过期，请到设置里更新」 |
| 网络不通 | 「连不上 AI 服务（可能是网络或额度），已跳过本轮补答案」 |
| 模型超时 | 「AI 响应太慢，已放弃这批；可以换个更快的模型」 |
| 题库文件损坏 | 「题库读不出来，已自动备份为 quiz_studio.broken-时间.db，请从备份恢复」 |

### 9.4 题库可分享、可合并

- **导出题库**：把当前卷子导出成 `.json`（不含 API Key），别人可以直接导入
- **导入题库**：支持多个 `.json` 合并，**同题按指纹去重**（与调研文档的 `fingerprint` 一致），冲突时提示「N 道题答案不一致，保留哪个版本？」
- 这样"我给同学发一份带答案的卷子"就成立了

### 9.5 首次使用引导（3 步卡片）

1. 「拖一份卷子进来，或者点『载入示例』试试」
2. 「没答案？设置里填个 AI Key 就能自动补」
3. 「做完点提交，我会告诉你每道错题错在哪」

第一次打开且题库为空时显示，有卷子后自动隐藏。

### 9.6 与 M1~M4 的关系

| 里程碑 | 面向开发者的功能 | 面向用户必须补的 |
|---|---|---|
| M1 | 极性感知补答案 | 无 Key 时的降级提示（9.1） |
| M2 | 自选模型 | 设置页 UI（9.2） |
| M3 | 错题分析 | 错因展示文案（9.3 风格） |
| M4 | 存量修正 | 导入/导出题库 + 冲突提示（9.4） |
| 新增 M5 | — | 首次引导（9.5）+ 全流程"无 Key 也能用"回归测试 |

### 9.7 验收补充（面向其他用户）

1. 一台**没装 Python、没配 Key** 的机器：双击 exe 能打开、能导入有答案的卷子、能判分、能看解析
2. 配错 Key：只弹一句提示，不影响继续做题
3. 从 A 同学导出 `.json` → B 同学导入：题目、答案、解析完整，重复题不重复出现
4. 断网状态下：所有本地功能正常，AI 功能给出明确提示而不是卡死
