# QuizStudio · 通用答题系统

一个可以**自己导入卷子**的答题系统：导入 → 自动按章节分类 → 在线作答 → 提交判分 →
**AI 判断对错（含主观题阅卷）+ 归纳错误点 + 指出薄弱知识点**。

它和同一目录上一级的 `java_quiz.html`（东软题库）是**两个独立项目**，互不影响：
`java_quiz.html` 一行没改，本题库有自己的目录、自己的端口（8770）、自己的 localStorage / SQLite。

## 一、怎么用

1. 双击 `start_quiz_studio.cmd`（需要 Python 3.8+，Windows 自带 `py` 即可）。
2. 浏览器自动打开 `http://127.0.0.1:8770/`。
3. 「题库 · 导入」→ 粘贴卷子文本，或点「选择文件」选 `.txt` / `.md` / `.json` → 「解析预览」→「保存到题库」。
4. 「答题」里作答 → 「提交评分」→ 自动跳到「诊断报告」。
5. 报告里有：正确率、各章正确率条、薄弱知识点、错题订正、AI 诊断（错误点归纳 + 薄弱点 + 三天复习安排），
   还可以「导出 Markdown 报告」。

想马上看效果：点「载入示例」会载入 `demo-bank.txt`（13 单选 + 3 多选 + 5 填空 + 5 判断 + 3 问答 + 2 编程，共 31 题）。

## 二、导入格式

不用严格排版，能识别常见写法。最小可用格式：

```
1. Java 中 int 占几个字节？
A. 1
B. 2
C. 4
D. 8
答案：C
```

### 题型分节（可选，但对排版和分值有好处）

```
## 一、单选题（每题 2 分）
## 二、多选题（每题 3 分）
## 三、填空题（每题 2 分）
## 四、判断题（每题 1 分）
## 五、问答题（每题 5 分）
## 六、编程题（每题 10 分）
```

识别关键词：单选 / 多选 / 不定项 / 判断 / 填空 / 简答 / 问答 / 论述 / 名词解释 / 编程 / 程序设计 / 综合 / 计算。
**不写分节也能用**，会按内容自动判断：有选项=选择（答案多个字母=多选）、有 `____`=填空、
答案是「对/错」=判断、含「编写/编程/程序」关键词=编程、其余=简答。

### 每道题可写的行

| 写法 | 作用 |
|---|---|
| `1.` `1、` `1)` `（1）` `第1题` | 题目开头 |
| `A. xxx` `B、xxx` `C) xxx` `D．xxx` | 选项（也支持一行写多个：`A. 甲  B. 乙  C. 丙`） |
| `答案：C` / `答案：对` / `【答案】xxx` | 标准答案 |
| `参考答案：……`（可多行，代码整段跟随） | 主观题参考答案 / 评分依据 |
| `解析：……` / `考点：……` / `【解析】……` | 解析 |
| `章节：第 3 章` 或 `章节：循环结构` 或题干前 `[第3章]` | **手动指定章节**，不写就自动分类 |
| `分值：5` | 单题分值 |

### JSON 导入

数组，或 `{"title":"...","questions":[...]}`，字段中英文都行：

```json
[{
  "type": "single",
  "stem": "下列哪个是接口的实现关键字？",
  "options": {"A": "extends", "B": "implements"},
  "answer": "B",
  "exp": "类实现接口用 implements",
  "ch": 9,
  "score": 2
}]
```

`type` 取 `single|multi|blank|judge|short|code`，也可直接写中文「单选/填空/判断/问答/编程」。

## 三、自动分章节

内置 13 个 Java 章节的关键词加权规则（沿用 `java_quiz` 项目里实测过的分类器）：
JDK/JVM/编译运行 → 1；数据类型/运算符 → 2；分支 → 3；循环 → 4；方法 → 5；数组 → 6；
类与对象 → 7；继承与多态 → 8；抽象类与接口 → 9；异常 → 10；字符串与常用类 → 11；
集合 → 12；JDBC → 13。匹配不到归入「其他 / 综合」。

规则是纯前端的，想改章节名或加科目，直接改 `index.html` 里的 `CHS` 与 `R_STEM / R_CODE` 两张表即可
（每题也可以写 `章节：` 覆盖自动结果）。

## 四、判分规则

| 题型 | 判定方式 |
|---|---|
| 单选 / 多选 | 本地比字母（大小写、顺序无关） |
| 判断 | 对/正确/√/T 与 错/错误/×/F 归一化后比较 |
| 填空 | 忽略空格标点、全半角、大小写；`/`、`、`、`；` 视为同义答案；多空按 `|` 或 `；` 分隔逐空比对，部分对记「半对」给一半分 |
| 问答 / 编程 | **提交后由 AI 阅卷**：完全正确 / 部分正确 / 错误，并给一句话点评（0~1 得分比例） |

## 五、AI 说明

- 用的是**完全免费、不需要注册和 API Key** 的 Pollinations 文本接口（`text.pollinations.ai`），
  和 `java_quiz` 项目同一条通道；由本地 `server.py` 代理，避免浏览器跨域。
- 这条免费通道有**硬性限流：每 IP 每 45 秒只放行 1 次请求**（报文 `FREE_LIMIT: 1 reply every 45 seconds per IP`）。
  `server.py` 里做了限流闸门（`MIN_AI_GAP = 46`）＋ 按报文 `Retry after Ns` 自动等待重试，所以
  **整套流程固定是「先判主观题 → 再写诊断」两发请求，串行排队，正常 1–2 分钟出结果**。
- 提交后**马上**返回客观题结果，AI 在后台异步跑，页面每 2.5 秒轮询一次，
  主观题判分和文字诊断完成会自动补进报告。
- AI 提示词要求输出三段：**一、错误点归纳（按题号）二、薄弱知识点（按优先级）三、三天复习安排**。
- 失败时报告里会显示原因，并给出**规则版结论**（各章正确率 + 薄弱章节），
  可以点「重新请求」再试。完全不联网也能用：客观题判分、分章统计、错题订正全部是本地算的。
- **想又快又稳：接自己的大模型。** 同目录的 `quiz_studio_llm.json` 已按「智谱 BigModel 免费模型」预置好，
  只差一个 Key：

  1. 打开 <https://bigmodel.cn> 登录 → 控制台 → API Keys → 新建并复制（形如 `xxxxxxxx.yyyyyyyy`）；
  2. 粘进 `quiz_studio_llm.json` 的 `api_key`（或设环境变量 `ZHIPU_API_KEY`）；
  3. `py -3 _dev\test_llm_connection.py` 自检一句，通了就重启 `server.py`。

  ```json
  {
    "api_key": "你的智谱Key",
    "base_url": "https://open.bigmodel.cn/api/paas/v4",
    "model": "glm-4-flash",
    "min_gap": 1,
    "judge_batch": 8,
    "max_judge_calls": 25
  }
  ```

  免费可用：`glm-4-flash`（默认）、`glm-4.5-flash`、`glm-z1-flash`。
  任何 OpenAI 兼容接口都能用（DeepSeek / 通义 / 硅基流动 / 本地 Ollama 等），
  走 `base_url + /chat/completions`，不用改代码。

  | 配置项 | 免费通道 | 自带 Key 默认 | 说明 |
  | --- | --- | --- | --- |
  | `min_gap` | 强制 46s | 0s | 相邻两次外呼最小间隔；免费通道是硬限流，配置文件改不小 |
  | `judge_batch` | 强制 14 | 20 | 单批判几题 |
  | `max_judge_calls` | 强制 2 | 20 | 最多几批，`batch × calls` = 一次提交能判的题数 |

  智谱免费档有 QPS 限制，所以预置成「1 秒间隔、8 题/批 × 25 批」＝ 一次提交可判 200 题，
  整份统一练习-1 正好一轮判完。

  实测（`glm-4-flash`，2026-11-17）：单次请求约 2.8 秒；第 8 章 14 题（2 批 + 1 次诊断）
  端到端 41 秒，14/14 判定齐全，错题都带出了「正确答案：X」。对比免费通道同一批要 90 秒以上。

- 带 Key 的 `quiz_studio_llm.json` 不会通过 HTTP 暴露：`server.py` 的静态兜底有黑名单，
  `/quiz_studio_llm.json`、`/quiz_studio.db`、`/server.py`、`_dev/`、`_import/`、`*.bak*` 一律 404。

## 六、数据在哪

- 题库与作答：浏览器 localStorage（键 `quizstudio_v1`），换浏览器/清缓存会丢，
  所以题库卡片上有「导出 JSON」，重要卷子建议导出一份备份。
- 提交记录与 AI 结果：`quiz_studio.db`（SQLite，服务端生成）。
- 端口 8770，只监听 `127.0.0.1`，不对外。

## 七、常见问题

| 现象 | 处理 |
|---|---|
| 右上角显示「未连接本地服务」 | 没启动 `server.py`。双击 `start_quiz_studio.cmd` 后从 `http://127.0.0.1:8770` 打开（直接双击 index.html 是 `file://`，只能用本地规则判分） |
| 端口被占用 | 改 `server.py` 里的 `PORT`，同时改 `start_quiz_studio.cmd` 里的地址 |
| 某题分错章节 | 在那道题下加一行 `章节：第 N 章`，重新导入 |
| 填空题判错 | 答案里写全同义答案：`答案：main/main方法` |
| AI 一直转圈 | 免费通道 45 秒才放行 1 次，等 1–2 分钟属正常 |
| 提示 402 / 429 限流 | 同一 IP 45 秒内发了第二次请求。服务端会自动等待重试；仍失败就点「重新请求」，或填自己的 Key |
| 想批量改题 | 导出 JSON → 改 → 重新用 JSON 导入 |

## 九、大题直接进 Eclipse（可选）

答题页里「编程题」下面有按钮 **「在 Eclipse 里作答」**，点一下：

1. 服务端在工程 `src` 下生成/覆盖**同一个文件** `<package>/Playground.java`（单文件模式）：
   - 文件头是**完整题干**（卷名 / 题号 / 题型 / 分值 / 生成时间）；
   - 题目里给了父类（如 Person、Goods），就把父类**原样放进文件**，标注「不要改」；
   - **不给任何空壳**：文件里除了题目注释，就只有题目自带的类（父类等），要写的类由你自己建，写完就交；
   - 「改错题」则把题目里的程序原样放进去（若含 `public class` 会去掉 `public`，避免和文件名冲突）。
2. 用 `eclipse.exe --launcher.openFile` 把它推到 Eclipse 打开；Eclipse 没开就顺带启动。
3. **提交时自动回填**：点「提交评分」会先把 Playground.java 读回来，去掉题库头注释，
   把纯代码写进对应大题的答题框（只覆盖你真的动过的文件——文件大小和生成时一样就视为没动，
   不会盖掉你手写的答案），再出判分与 AI 诊断。

   **默认不清空文件**：Eclipse 那时往往还挂着这个编译单元的模型，从外部一改动就容易弹
   「访问编译单元时出错：索引值超出边界」。留着内容不影响使用 —— 下次点「在 Eclipse 里作答」会整体覆盖
   （同一道题重开会保留你写的代码，换题才会覆盖）。想要老行为就把 `quiz_studio_ide.json` 的
   `clearOnSubmit` 改成 `true`；写文件也改成了临时文件 + 原子替换，尽量避开 Eclipse 的读取窗口。

   如果 Eclipse 已经弹过那个错：在工程上按 **F5** 刷新，或右键 → Refresh，必要时 Project → Clean。

配置在同目录 `quiz_studio_ide.json`（改完不用重启，每次请求会重读）：

| 字段 | 说明 |
| --- | --- |
| `eclipse_exe` | Eclipse 可执行文件；留空自动找（先找正在运行的 Eclipse） |
| `project_src` | 工程的 `src` 目录，文件生成在它下面 |
| `package` | 包前缀，实际包名是 `<package>.<卷名>_<题号>`（每题独立包，Student/Person 这类类名不会撞） |
| `enabled` | 设 `false` 可整体关掉这个功能 |

接口：`POST /api/code/open {bankId,qid}`、`POST /api/code/harvest {bankId}`（读回+删除）、`POST /api/code/close {bankId[,qid]}`（只删）、`GET /api/code/list`。
生成记录写在 `_opened_code.json`，进程重启也不会丢，提交时仍能删干净。
## 十、多科目 + 章节（自动 / 手动）

**导入时选科目**：导入区多了两个下拉——

| 下拉 | 说明 |
| --- | --- |
| 科目 | 列出已有科目，最后一项「＋ 新建科目…」可以现场建（例如「高等数学」「数据结构」） |
| 分章 | `自动分章` / `先全部未分类（之后手动分）` |

**自动分章规则**（跟着科目走）：

- 科目名里含 `Java` → 沿用 13 章关键词分类（Java 概述 / 数据类型 / … / JDBC）；
- 其它科目 → 认题目里的显式标注：`章节：第 1 章 · 极限`，或者正文里的「第 N 章 名字」；
- 两者都没有 → 先落到「未分类」，之后再手动分。

**手动分章**：答题卡上每道题的章节标签现在是个下拉

```
第 3 题  [单选题]  [第 1 章 · 极限 ▾]   10 分
                    未分类
                    第 1 章 · 极限
                    第 2 章 · 导数
                    ＋ 新建章节…
```

选一下就改（自动存库、同步服务器、章节页立刻跟着变）；选「＋ 新建章节…」可以现场加新章节。

**数据结构**：章节挂在那份卷子自己身上 —— `bank.subject`（科目）+ `bank.chapters`（`[{id, name, tag}]`）。
老卷子没有 `chapters` 时自动回退 Java 的 13 章，历史数据不受影响。题库列表按科目分组显示，例如「Java语言程序设计III（21 卷）」。

顺带修掉一个会崩的 bug：原来章节页用 `CHS[k-1].tag` 取标签，章节号 > 13 会抛异常导致整页白屏，现在从卷子自己的 `chapters` 里取。
### AI 分章

章节页右上角有个 **`AI 分章`** 按钮：把当前卷子里**还没章节**的题（最多 200 题，每批 20 题）发给模型，
让它复用现有章节名（对不上才新建），回来直接落到 `bank.chapters` 里。全程静默执行，不弹窗。

- 只处理 `ch = 0` 的题，已分好的不动；
- 没有未分类的题时按钮自动隐藏；
- 实测（`glm-4-flash`）：4 道 Java 题 → 异常处理 / 集合框架 / 循环结构 / JDBC，全对，约 4 秒。

接口：`POST /api/chapters {subject, chapters:[名字], questions:[{id,stem,opts}]}` → `{map:{qid:章节名}}`。
### 导入时自动补答案（AI 作答 → 入库）

点「保存到题库」时，**凡是还没有标准答案的题，会先让 AI 逐题作答**，答案跟着卷子一起写进 SQLite，之后判分就能直接用标准答案比对。

- 一次最多 400 题（每批 20 题），期间按钮显示「AI 补答案…」；
- 单选/多选按字母归一（多选按字母排序），判断题转成 对/错，填空题写进 `answer`+`ref`，简答/编程题写进 `ref`（参考答案）；
- 原来没答案的题题型本身是猜的：如果 AI 给出多个字母、题干又是「哪些/多选/至少…」，会自动把题型纠正成多选；
- 打上 `_aiAnswer: 1` 标记，方便之后区分「AI 补的答案」和「卷子自带的答案」；
- 接口：`POST /api/answers {questions:[{id,type,stem,opts}]}` → `{map:{qid: 答案}}`。

准确率实测（用题库里已有的标准答案做基准，抽 20 道单选/多选/判断/填空）：

| 模型 | 耗时 | 准确率 | 说明 |
| --- | --- | --- | --- |
| `glm-4-flash` | 0.6 秒/题 | **13/20 = 65%** | 其中 2 题是题库答案本身坏的（填了 `flast`），扣掉约 72% |
| `glm-4.5-flash` | 8~13 秒/题 | — | 是**推理模型**（先输出 reasoning_content），单题要 300+ tokens，不适合批量补答案 |
| 本地 `qwen2.5-3b`(CPU) | 14 秒/题 | 10/20 = 50% | 只做断网兜底 |

误判集中在「代码执行结果推演」这类题（`do-while`、`if` 分支、`switch` 落点），概念题基本全对。

### 通道顺序

`quiz_studio_llm.json` 里 `providers` 按顺序尝试：

1. `zhipu · glm-4-flash`（默认，快、免费）

### 历史题库补答案（一次性脚本）

```cmd
py -3 _import\backfill_answers.py --dry              # 先看要补多少题
py -3 _import\backfill_answers.py                    # 全部补（客观题答案 + 主观题参考答案）
py -3 _import\backfill_answers.py --bank bank_ch08    # 只补一卷
py -3 _import\backfill_code_answers.py               # 编程题参考答案重写成可编译代码
```
