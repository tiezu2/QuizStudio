## 1. 主流题库是「按原卷」还是「按章节/知识点」组织？—— 结论：**两者都有，且几乎都是"两套视图 + 一个池"**

- **牛客网：明确的"套卷 + 知识点"双入口**。题库一级入口直接拆成 `专项练习 / 笔试真题 / 面试真题 / 在线编程` 四个并列 Tab（[牛客题库页](https://www.nowcoder.com/exam/company)）。其中"笔试真题"列表里全是 `2025年春招-阿里云-研发岗-第一批笔试`、`中国银行2025春招笔试-模拟卷2` 这类**带公司/年份/批次的原本卷**，点进去是一张固定试卷；而"专项练习"是按知识点/岗位方向组织的练习流。官方使用指南还补充了一个关键细节：题库里除了分类练习，还有一个**不做归类的全量题池**页（站内原文显示为"试题\*\*\*"，"就是所有的试题全部在这里，没有给你归类"），并且"智能专项练习……会以组卷的形式来出现"——也就是说**专项练习本身也是动态组卷**，而不是静态题表（[牛客网使用指南](https://www.nowcoder.com/discuss/353153992161173504)）。

- **力扣 LeetCode：几乎没有"原卷"概念，是"题目 + 标签"平铺 + 题单式编排**。题库首页直接把 `数组2449 / 字符串971 / 哈希表912 / 动态规划761 …` 等几十个 tag 连题量一起平铺出来，题目按 tag 过滤（[leetcode.cn/problemset](https://leetcode.cn/problemset/)）。它没有"2024 秋招第几批笔试"这种套卷实体，只有竞赛卷和"学习计划/LeetBook"，而这类是**按知识点分篇的推荐路径**（例如官方整理的"Re：从零开始的力扣刷题生活"就是按"数组篇 / 链表篇 / 哈希表篇"分小节，[coding101 收录版](https://raw.githubusercontent.com/LoveOrange/coding101/refs/heads/main/docs/leetcode/re-leetcode/index.md)）。

- **考试星（B 端严肃考试）：章节分类与套卷组卷并存，且分类是多级树**。"可根据专业、学科、章节等细分自定义试题库管理系统目录，支持无限级分类管理"，"根据试题的难度、题型、章节等分类录入"；组卷侧支持"选题组卷、抽题组卷、随机组卷、综合组卷"四种（[题库考试系统使用指南](https://www.kaoshixing.com/news/n544)）。其对外题库中心页也把试题按"一级 / 二级 / 三级"分类展示（[考试星题库中心](https://www.kaoshixing.com/core/s18)）。

- **问卷星：以"组卷"为中心，题库是抽题来源，靠文件夹做隔离**。"快速建立题库……支持题库随机抽题"；管理上用"试卷文件夹"按年级/学科划分并指派子管理员（[问卷星校园在线考试](https://www.wjx.cn/app/themehtml/onlinetest.aspx)）。它的模型更接近"题库 → 抽题生成试卷"，而不是"原卷即题目容器"。

- **超星 / 学习通（未完全验证）**：多所高校公开的《超星智慧考试系统使用手册（教师）》标题本身就说明其考试模块包含"题库 + 抽题组卷 + 随机抽题"，并且题库会与课程关联（[东北林业大学超星智慧考试系统使用手册](https://zxjx.nefu.edu.cn/system/_content/download.jsp?urltype=news.DownloadAttachUrl&owner=1623065642&wbfileid=D3CE79697330695A984C957395B0C049)、[菏泽医专超星在线考试指南](https://jwc.hagmc.edu.cn/system/_content/download.jsp?urltype=news.DownloadAttachUrl&owner=2007602964&wbfileid=4737133)）。但这些是受访问控制的 PDF，我**只验证到标题与检索摘要，正文未能逐字核对**，因此本节不对超星的具体表结构下结论。

- **规律总结**：C 端刷题产品（牛客、力扣）以**知识点/标签**为主要组织轴，"套卷"只是其中一种入口；B 端考试（考试星、问卷星）以**题库 → 组卷 → 试卷 → 考试场次**为主链条，章节只是题库内的分类维度。**没有任何一家是"只按原卷"组织的**——因为只要存在练习模式，就必然需要跨卷的题目视图。

## 2. 一道题出现在多个卷子里，数据模型怎么办？—— 结论：开源主流是**"题目只存一份 + paper_questions 多对多"**，副本模型是公认的反模式

- **主流开源实现：单份 `questions` + 关联表 `paper_questions`**。以 ExamFlow 的数据库设计为例：`questions` 表独立存在（`category_id`、`type`、`content`、`options`(JSON)、`answer`、`score`），`papers` 只是一张"壳"（标题/时长/总分），两者通过 `paper_questions(paper_id, question_id, score)` 关联，**主键就是 (paper_id, question_id) 复合主键**（[ExamFlow 数据库设计](https://gitcode.com/aadkwn/agentteam-exam-system/blob/main/design/%E6%95%B0%E6%8D%AE%E5%BA%93%E8%AE%BE%E8%AE%A1.md)）。

- **关联表必须携带"卷内属性"，这是关键设计点**。另一个同类开源项目（Spring Boot 在线考试）的 ER 图里，`paper_questions` 用独立自增主键，额外带 `score` 和 `sort_order`；题目本身另挂 `subject_id` + `knowledge_point_id`（[在线考试系统 ER 图](https://gitcode.com/L1F666/agentteam-online-exam/blob/master/design/ER%E5%9B%BE.puml)）。即：**题目内容一份（去重），题目在某卷中的分值/顺序/分区多份（随卷）**。这正是"一题多卷"分歧的正解——分歧不在题目内容，而在卷内属性。

- **业界文章明确把"题库"和"试卷"解耦**：一篇被广泛引用的考试系统设计文写道"**题库与试卷没有关系，是以试题为对象的分类管理罢了**。将试题归类后在添加试卷动作时选择试题比较方便"；它的表结构里 `company_question.database_id` 指向**题库（分类）**而不是指向试卷，试卷与考试才是多对多——"考试时间、及格分数这类字段不应加在试卷上……应加入在考试表中"（[论某教育机构考试系统设计](https://cloud.tencent.com.cn/developer/article/1534028)）。

- **副本模型（每卷一份）在开源里的真实样子，以及它为什么被诟病**：国内大量 SpringBoot 毕设型考试系统就是这种结构——`exampaper`（试卷）+ `examquestion`（试题，带 `exampaper_id 所属试卷id（外键）`）+ `examrecord` + `examredetails`，试题**从属于试卷**，同一道题出现在两套卷里就是两条记录（[0198springboot 疫情打卡健康评测系统 README，第 4.3.2 节表结构](https://github.com/GraduationProject-springboot/0198springboot)）。这种做法上手最快，但代价明确：改一道错字要改 N 条；同一题在不同卷里答案不一致时无法判定谁是对的；跨卷统计"这道题正确率"要先做去重聚类。

- **副本模型的"合理内核"要保留，但应改为快照而非副本**。业界给出的替代方案是：**题目存一份，历史可追溯靠"双快照"**——"答题记录表要同时落试卷快照和题目快照：试卷会改版、题目会被编辑，没有快照，三个月后回看'这次考试到底答了什么'就对不上号"（[答题考试系统的题库侧工程实现](https://developer.aliyun.com/article/1764720)）。这解决了副本模型想解决的"历史不能变"问题，又不产生同题多答案。
  - **单份 + 多对多**：优点——改一次全局生效、天然可做跨卷题目统计/去重、存储省；缺点——改题会影响未加锁的历史，必须靠快照兜底；删题要先查引用（外键/软删）。
  - **每卷副本**：优点——卷与卷完全隔离、可以任意改某一卷不影响别人；缺点——数据冗余、同题多答案冲突、无法做全局正确率、题目池无法维护。
  - **推荐组合**：`question` 单份 + `paper_question` 多对多 + `attempt_answer.question_snapshot` 作答时快照。三者叠加，兼顾唯一性与历史不可变。

## 3. 常见数据表怎么拆、主键与关联怎么设

- **题目侧三张表：`questions` 主表 + 选项（JSON 列或 `question_options` 子表）+ 分类/知识点**。ExamFlow 用 `options TEXT（JSON 数组）`、`answer TEXT（选项索引逗号分隔）`（[ExamFlow](https://gitcode.com/aadkwn/agentteam-exam-system/blob/main/design/%E6%95%B0%E6%8D%AE%E5%BA%93%E8%AE%BE%E8%AE%A1.md)）；ER 图版本则更规整：`subjects` → `knowledge_points(subject_id)` → `questions(subject_id, knowledge_point_id)`（[ER 图](https://gitcode.com/L1F666/agentteam-online-exam/blob/master/design/ER%E5%9B%BE.puml)）。取舍：**选项少、不参与检索 → JSON 列足够；选项要统计选择率（考试星就提供"选项选择率"）→ 必须拆子表**（[考试星指南](https://www.kaoshixing.com/news/n544)）。

- **试卷与题目分离 + 关联表带卷内属性**：`papers(id, title, subject_id, total_score, duration, status)`、`paper_questions(paper_id, question_id, score, sort_order, [section_id])`。主键两种写法都成立：**(paper_id, question_id) 复合主键**（ExamFlow）或 **代理主键 + UNIQUE(paper_id, question_id)**（ER 图版）。后者更利于后续加审计列、做逻辑删除与分库分表。
  - 反向索引必须有：`KEY (question_id)`，否则"这道题出现在哪些卷子"（改题前的影响面评估、删题前查引用）会全表扫。

- **"考试场次"必须是独立表，不要把时长/及格分塞进试卷**。腾讯云那篇文章专门强调过这点：试卷与考试是多对多，`start_time / time_limit / pass_score` 属考试表（[原文](https://cloud.tencent.com.cn/developer/article/1534028)）。ER 图版也是 `papers → exams(paper_id) → exam_records(exam_id, student_id)`（[ER 图](https://gitcode.com/L1F666/agentteam-online-exam/blob/master/design/ER%E5%9B%BE.puml)）。

- **作答侧两张表 + 两个唯一约束**：`exam_records` / `exam_answers`。ER 图里明确标注了 `UNIQUE(exam_id, student_id) 一场考试一名学生仅一条记录` 与 `UNIQUE(record_id, question_id) 一条记录一道题仅一条答案`（[同上](https://gitcode.com/L1F666/agentteam-online-exam/blob/master/design/ER%E5%9B%BE.puml)）。这两个唯一键是防重复提交的最后一道闸，比业务代码判断可靠。

- **材料题（大题带若干小问）不要冗余存储，用父子结构**：材料本体一条父记录，子题 `parent_id` 指向父题，判分时子题独立计分；"把材料塞进每道子题冗余存储的做法，改一处材料要同步 N 条记录，是题库系统的经典事故源"（[阿里云文章](https://developer.aliyun.com/article/1764720)）。

- **主键选型**：中文圈开源普遍用 `BIGINT` 自增或雪花 ID；关联表**不要用外键强约束 + CASCADE 混用**（ExamFlow 对 `paper_questions.paper_id` 用了 CASCADE，删卷即删关联，但删题时不能级联删除别人还在用的卷），更稳的做法是软删 `status` + 应用层校验引用。

## 4. 练习模式的五个入口，以及各自对应什么查询

- **入口清单有现成样例**：希赛题库把入口做成 `章节练习 / 模拟考场 / 历年真题 / 每日一练 / 习题练习（核心知识点）/ 高频错题` 六个并列入口（[希赛基金从业题库页](https://m.educity.cn/jjcy/5411102.html)）。牛客是 `专项练习 / 笔试真题 / 面试真题 / 在线编程`（[牛客题库页](https://www.nowcoder.com/exam/company)）。两者可以互相印证：**"套卷型"入口和"知识点型"入口必须同时存在**。

- **顺序练习（全库/单库顺序刷）**：本质是按稳定键游标翻页。`SELECT id FROM question WHERE subject_id=? AND status=1 AND id > :lastId ORDER BY id LIMIT 20;` —— 用 `id > lastId` 而不是 `LIMIT offset`，否则深翻页会越刷越慢。

- **章节练习（知识点）**：走 `question_chapter` 关联表。`SELECT q.* FROM question q JOIN question_chapter qc ON qc.question_id=q.id WHERE qc.chapter_id IN (:subtree) ORDER BY q.id;` 章节是树时，用 `chapter.path LIKE '/1/12/%'` 一次拿子树比递归 CTE 更省（MySQL 8 以下尤其）。

- **随机组卷 / 智能组卷**：不是 `ORDER BY RAND()`，而是"规则翻译成查询条件 + 去重 + 配平"，并且**必须可重放**——"抽题过程要可重放（记录随机种子或抽题日志），否则考后申诉无法复核'为什么抽到这道题'"（[阿里云文章](https://developer.aliyun.com/article/1764720)）。落地：`exam` 表存 `random_seed`，组卷结果落 `exam_question`（快照表），而不是每次现场抽。考试星的四类组卷（选题/抽题/随机/综合）就是这个谱系（[考试星](https://www.kaoshixing.com/news/n544)）。

- **错题重做**：`wrong_question(user_id, question_id)` 主键即 (user_id, question_id)，查询 `WHERE user_id=? AND mastered=0 ORDER BY last_wrong_at DESC`。注意两点：**归集要异步 + 幂等**——"错题归集进异步任务队列……错题归集带幂等键，避免重练列表里同一道错题出现两遍"（[阿里云文章](https://developer.aliyun.com/article/1764720)）；`question_id` 必须指向**去重后的题目 ID**，否则同一道题在不同卷子错一次就存多条，这是副本模型的直接受害者。

- **模拟考试 / 真题实战**：查 `exam` + 预生成的试卷快照。`SELECT * FROM exam WHERE id=? AND start_at<=NOW() AND end_at>=NOW()`，题目从 `exam_question`/`paper_snapshot` 读，**不从 `question` 实时读**——否则考试中途有人改题，同一场考试的考生看到的题干就不一致了（这正是"双快照"要解决的问题，见[阿里云文章](https://developer.aliyun.com/article/1764720)）。

## 5. "去重视图 / 独立题目池"在业界叫什么？

- **英文标准术语是 `item bank`，且它与 `item pool` 是同义词**。ERIC 的文献原文："ITEM BANKS, sometimes called 'item pools' 'question banks', 'item files', 'test item libraries' or 'item collections'…"（[ERIC ED317580](https://files.eric.ed.gov/fulltext/ED317580.pdf)）；韩国 KICE 的研究报告更直接："The term 'item bank' has been used interchangeably with other terms such as 'item pool,' 'item inventory,' and 'item database"（[KICE 报告](https://kice.re.kr/filedown8.do?fileNM=ORM200601400.pdf&filePath=/research/20130110/1357784744116_110)）。所以你要找的概念，**标准叫法是 item bank / item pool**，中文对应"题库 / 题目池"，不是什么私有名词。

- **中文商业题库里对应的商品化叫法是"母题"**：希赛的"经典母题"功能明确采用"**母题 + 变式**"模式——"每道母题对应 3-5 种变式题……针对'基金管理人禁止行为'这一高频考点，母题可能以'禁止承诺收益'为题干，变式题则改为'以下哪项不属于违规宣传行为'"（[希赛](https://m.educity.cn/jjcy/5411102.html)）。这实质上就是"一个知识点母题 + N 个派生变体"的父子结构，和材料题的 `parent_id` 是同一套建模手法。

- **国内题库运营语境里还有"母题库 / 试题库 / 题库池"的说法**，指的是与"试卷"解耦的唯一题目集合；腾讯云那篇文章的 `company_question_database`（题库=分类）+ `company_question.database_id` 就是这个池的落地形态（[原文](https://cloud.tencent.com.cn/developer/article/1534028)）。

- **"去重视图"在工程上落成一个唯一键 + 一个指纹字段**：把题干、选项做归一化（去空白、去标点全半角、选项排序）后取 SHA-256 存 `fingerprint`，对 `(subject_id, fingerprint)` 建唯一索引（或先建普通索引 + 冲突告警，人工裁决）。这是"去重"从产品概念变成数据库约束的最小实现。

- **配套的"统计视图"是题目池的另一半价值**：因为题目唯一，才能建 `question_stats(question_id, attempt_count, correct_count, choice_distribution)`，支撑"试题利用率、对错排名和选项选择率"这类分析（[考试星指南](https://www.kaoshixing.com/news/n544)）。副本模型下这张统计永远做不准。

## 6. 对我们这个 Java 题库的建议

### 6.1 先定性：我们现在的模型是哪一种

我们目前是「**每个卷子各存一份副本**」：`试卷 → 试题(exampaper_id 外键)`，同题多卷 = 多条独立记录。这在开源里是有先例的（[0198springboot 那类 SpringBoot 毕设结构](https://github.com/GraduationProject-springboot/0198springboot)：`examquestion.exampaper_id 所属试卷id（外键）`），但它是**已知反模式**，代价就是你说的：数据冗余、同题多答案易冲突、无法做跨卷统计、错题本按副本记导致同题重复、改题要批量改。

目标态不是"把副本删掉就完事"，而是三件套：

> **题目内容一份（去重池） + 卷内属性多份（关联表） + 作答时快照（历史不可变）**

这正好对应 ExamFlow 的 `questions / paper_questions`（[ExamFlow](https://gitcode.com/aadkwn/agentteam-exam-system/blob/main/design/%E6%95%B0%E6%8D%AE%E5%BA%93%E8%AE%BE%E8%AE%A1.md)）、ER 图版的 `knowledge_points / paper_questions(score, sort_order)`（[ER 图](https://gitcode.com/L1F666/agentteam-online-exam/blob/master/design/ER%E5%9B%BE.puml)）和阿里云文章的"答题记录存双快照"（[阿里云](https://developer.aliyun.com/article/1764720)）。

### 6.2 目标表结构（MySQL 8 / InnoDB，可直接落地）

```sql
-- ① 科目与章节（章节树用自关联 + path 前缀，便于取子树）
CREATE TABLE `subject` (

  `ref_chapter_id` BIGINT  NULL COMMENT '章节练习时记录章节，便于断点续练',

-- ⑨ 作答明细：题目内容快照落在这里（历史不可变）

  `question_snapshot` JSON       NOT NULL COMMENT '题干/选项/答案/解析快照',
  `seq_no`            INT        NOT NULL,
  `user_answer`       MEDIUMTEXT NULL,
  `is_correct`        TINYINT    NULL,
  `score`             DECIMAL(5,2) NULL,
  PRIMARY KEY (`attempt_id`,`question_id`),
  KEY `idx_aa_question` (`question_id`)

CREATE TABLE `wrong_question` (
  `user_id`      BIGINT   NOT NULL,
  `question_id`  BIGINT   NOT NULL,
  `wrong_count`  INT      NOT NULL DEFAULT 1,
  `last_wrong_at` DATETIME NOT NULL,
  `mastered`     TINYINT  NOT NULL DEFAULT 0,
  PRIMARY KEY (`user_id`,`question_id`),
  KEY `idx_wq_user_redo` (`user_id`,`mastered`,`last_wrong_at`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;
```

**几个必须坚持的点**（每一条都能在来源里找到依据）：

1. `paper_question.score` 必须存在关联表**而不是** `question` 上——分值随卷变（ExamFlow 与 ER 图版都这么设计）。
2. `idx_pq_question` 反向索引不能省，否则"这道题还被哪些卷子引用"只能全表扫（ExamFlow 的复合主键天然有此能力，代理主键版必须显式建）。
3. 考试必须读快照，不读 `question` 实时表（[阿里云"双快照"](https://developer.aliyun.com/article/1764720)）。
4. `exam` 与 `paper` 分离，时长/及格分/开考时间放 `exam`（[腾讯云文章](https://cloud.tencent.com.cn/developer/article/1534028)）。
5. 材料题走 `parent_id`，不要把材料冗余进每个小问（[阿里云](https://developer.aliyun.com/article/1764720)）。

### 6.3 迁移步骤（可停机窗口小、可分批发版）

**Step 0 — 摸底与冲突报告（只读，不动数据）**
```sql
-- 用"归一化题干+选项+答案"做指纹，先看重复到底有多严重
SELECT fingerprint, COUNT(*) AS cnt, COUNT(DISTINCT answer) AS distinct_answers
FROM (
  SELECT SHA2(CONCAT_WS('|', subject_id, type,
           TRIM(REGEXP_REPLACE(content,'\\s+','')),
           TRIM(REGEXP_REPLACE(IFNULL(options,''),'\\s+','')),
           TRIM(answer)), 256) AS fingerprint,
         answer
  FROM examquestion
) t
GROUP BY fingerprint
HAVING cnt > 1
ORDER BY cnt DESC;
```
输出两类：`distinct_answers = 1` 的是**纯冗余副本**（可直接合并）；`distinct_answers > 1` 的是**同题多答案冲突**，必须人工裁决——先别写库，列清单出来 review。

**Step 1 — 建新表，不改旧表**：执行上面 6.2 的 ①②③④⑤⑥⑦ 建表脚本，旧表 `exampaper/examquestion` 原样保留（双写期谁都不许删）。

**Step 2 — 回填唯一题目池 `question`**
```sql
INSERT INTO question (subject_id, type, content, options, answer, analysis, fingerprint, content_ver, status)
SELECT subject_id, type, content, options, answer, analysis, fingerprint, 1, 1
FROM (
  SELECT *, ROW_NUMBER() OVER (PARTITION BY fingerprint ORDER BY id) AS rn
  FROM (
    SELECT id, subject_id, type, content, options, answer, analysis,
           SHA2(CONCAT_WS('|', subject_id, type,
                TRIM(REGEXP_REPLACE(content,'\\s+','')),
                TRIM(REGEXP_REPLACE(IFNULL(options,''),'\\s+','')),
                TRIM(answer)), 256) AS fingerprint
    FROM examquestion
  ) x
) y
WHERE rn = 1;   -- 每个指纹只保留 id 最小的一条作为"母题"
```

**Step 3 — 建旧题号到新题号的映射表（迁移期的命根子）**
```sql
CREATE TABLE `migrate_q_map` (
  `old_question_id` BIGINT NOT NULL,
  `new_question_id` BIGINT NOT NULL,
  PRIMARY KEY (`old_question_id`)
);
-- 按 fingerprint 回连，而不是按 id 回连
INSERT INTO migrate_q_map
SELECT e.id, q.id
FROM examquestion e
JOIN question q
  ON q.subject_id = e.subject_id
 AND q.fingerprint = SHA2(CONCAT_WS('|', e.subject_id, e.type,
        TRIM(REGEXP_REPLACE(e.content,'\\s+','')),
        TRIM(REGEXP_REPLACE(IFNULL(e.options,''),'\\s+','')),
        TRIM(e.answer)), 256);
```

**Step 4 — 回填 `paper_question`（这一步把"副本"压成"关联"）**
```sql
INSERT INTO paper_question (paper_id, question_id, sort_no, score)
SELECT e.exampaper_id, m.new_question_id, e.examquestion_sequence, e.examquestion_score
FROM examquestion e
JOIN migrate_q_map m ON m.old_question_id = e.id
ON DUPLICATE KEY UPDATE            -- 同一卷里重复抽到同题时保留高分/先序
  score    = GREATEST(paper_question.score, VALUES(score)),
  sort_no  = LEAST(paper_question.sort_no, VALUES(sort_no));
```
> 注意：这一步会暴露一个业务问题——**同一张卷子内部本来就有重复题**。`ON DUPLICATE KEY` 会静默吞掉一条，跑完必须对账：`SELECT paper_id, COUNT(*) FROM paper_question GROUP BY paper_id` 与旧表 `SELECT exampaper_id, COUNT(*) FROM examquestion GROUP BY exampaper_id` 逐卷比对，差异卷人工确认。

**Step 5 — 回填章节关联（若有章节字段）**：`question_chapter` 从旧表的章节/知识点列 + 新表的 subject 推导，缺数据的题先挂到"未分类"章节，保证章节练习入口不空。

**Step 6 — 代码双写 + 灰度读**
- 写入路径：新增/编辑题目 → 写 `question`，同步维护 `paper_question`；同时继续写旧 `examquestion`（双写期，出问题可回滚）。
- 读取路径：用配置开关按 `subject_id` 灰度切到新表；练习模式（顺序/章节/随机/错题）**优先切**，考试链路最后切（考试要等 Step 7 的快照能力）。

**Step 7 — 考试链路切快照**：开考时生成 `paper_snapshot` 并写 `exam.snapshot_id`，作答写 `attempt_answer.question_snapshot`。此后改题不再影响任何历史考试。

**Step 8 — 观察期后下线旧结构**：把 `exampaper/examquestion` 改名为 `_bak_exampaper/_bak_examquestion`（不删），旧 SQL 用 `CREATE VIEW examquestion AS SELECT ... FROM paper_question JOIN question` 兼容一段时间，最后再物理删除。**建议至少保留一个完整学期的 `_bak` 表**。

**Step 9 — 补两张运营表**：`question_stats(question_id, attempt_count, correct_count, choice_distribution)` 与 `question_variant(parent_question_id, child_question_id)`（对应"母题+变式"，见[希赛](https://m.educity.cn/jjcy/5411102.html)）。这两张表只有在题目唯一化之后才有意义，所以放最后。

### 6.4 三个容易踩的坑（提前说清楚）

1. **`uk_question_fp` 不要第一天就上唯一索引**。真实题库里"题干相同但答案不同"（考同一法条的不同选项组合）很常见，唯一索引会让导入直接失败。**先建普通索引 + 冲突报表，人工裁决一轮后再升级为唯一索引。**
2. **不要给 `paper_question.question_id` 加 `ON DELETE CASCADE`**。ExamFlow 对 `paper_id` 用了 CASCADE（删卷清关联，合理），但删题若也级联，会静默毁掉历史试卷结构。删题一律走 `question.status=0` 软删 + 引用检查。
3. **迁移的核心风险不是 SQL 写不出来，是"同题多答案"的裁决没流程**。Step 0 的报告要先给业务方（教研/命题老师）签字，否则 Step 2 那个 `ROW_NUMBER() ... rn=1` 等于系统替人拍板了答案，后面一定会翻案。
